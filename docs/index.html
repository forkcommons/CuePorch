Keep the master. Publish the viewing copy.

CuePorch preserves and publishes video for public media stations and arts institutions. It keeps a hashed master of every work, delivers viewing copies through a PeerTube host you control, and lets a museum screen one film for one window without handing out the file.

  • Self-hosted

What it is

Built for institutions that cannot lose the original.

A station’s meeting archive or a museum’s loaned film outlasts any one hosting account. CuePorch separates the thing you must keep from the thing you show.

The master stays yours

Every import and upload is stored as a hashed object next to an SQLite database in your own library folder. python cueporch.py verify COLLECTION checks the stored files, and export_institution.py writes a portable export with media, hashes, agreements, case history and routes. Uninstalling removes program files separately from the library.

Publishing is a step, not a side effect

Imports start private. Delivery goes through a worker that applies the institution’s approval policy and records a receipt binding each work to its hosted video. Publication updates a stable institutional watch route once the destination has finished processing.

Capabilities

One library, six jobs.

Each item below is documented in the user manual and has a matching screen or endpoint in the source.

  • 01

    Move from Vimeo

    Preview an owner account, transfer privately, then publish what is eligible. Source IDs keep identically named cuts apart, and checkpoints avoid repeat transfers.

    • Captions and chapters carried over
    • Reports works that lack media
    • Exports an embed map as CSV

    Partial. Tested against a simulated source; production Vimeo sign-in is unobserved.

  • 02

    Publish on your own PeerTube

    Connect an existing PeerTube host, or have the launcher provision one with Docker Compose. CuePorch serves institution-controlled watch and embed routes that play the hosted copy.

    • Private first, public when approved
    • Playback, upload and replay tested with real PeerTube
    • Optional JavaScript Player API
  • 03

    Exhibit one film in many venues

    A grant ties one cut to one origin and one agreement window. The venue’s server asks CuePorch for a session and embeds the expiring player. Revoking one venue leaves the others playing.

    • Separate screening copy from the private master
    • Anonymous requests denied
  • 04

    Review, approve, respond

    Share a review link with an expiry, optional password and time-coded comments with replies and @mentions. Approval switches gate steps such as intake, captions, publication and restoration. Complaints open a case with history.

    • Versions kept; restore a previous cut
    • Per-link settings and device notifications
  • 05

    Go live and record

    Schedule events, prepare an RTMP encoder, or broadcast from the browser studio with scenes, slides, audience Q&A and polls. Record Studio captures camera and screen with a teleprompter.

    • Up to seven invited guests per occurrence
    • Registration, waiting room, DVR window, replay

    Live features need a live-enabled PeerTube host.

  • 06

    Give viewers a catalog

    A public Watch page with categories, search, channels and Staff Picks. Viewers can sign in, keep Watch Later, like videos and build collections. Operators get captions, alternate audio, chapters, analytics and team accounts.

    • Subtitles from WebVTT or SRT; optional TextFlowKit generation
    • Impressions, views and time watched

The Vimeo move

Preview, transfer privately, then publish.

The migration screen follows four steps, and nothing becomes public until an operator publishes it.

  1. Preview

    Read the owner account and see an inventory with the expected quality of each recovery before anything moves.

  2. Transfer privately

    Fetch the accessible media and captions. Hashes, checkpoints and exceptions are saved, so an interrupted run resumes.

  3. Deliver

    Eligible media goes to PeerTube privately. A receipt links each work to its hosted video and processing state.

  4. Publish

    Check retrieval quality, captions and visibility, then publish eligible imports and replace embeds using the exported map.

When the account owner has not supplied an original, CuePorch recovers the best advertised downloadable file and tells you if neither exists. Replacing embeds on sites outside your institution still requires edits by those site owners.

Exhibition

Lend a film without lending the file.

A museum visitor authenticates on the museum’s own site. The museum’s server presents the grant secret and receives a relative embed path with an expiry. CuePorch checks the grant on each player, caption and media request.

  • A grant names the cut, the allowed origin including scheme and port, and the agreement dates.
  • Each exhibitor gets a separate grant, so one revocation does not affect another venue.
  • A decision to suspend screenings for the work has broader effect than revoking a single grant.
  • An existing grant keeps playing the version selected when it was issued.

Venue server, from the HTTP integration table

# issue a screening session for one grant
POST /api/grants/<uid>/session
Authorization: Bearer <grant secret>

# response carries
{ "embed": "/screen/...", "expires": <unix time> }

# resolve the path against the CuePorch origin,
# then embed it with
<iframe referrerpolicy="origin" ...>

The installed acceptance runs exercised an authorized venue playing a viewing copy, an anonymous request being denied, and revocation and restoration. They used short fixtures.

Live events and recording

From a scheduled program to a saved replay.

Schedule and transmit

  • Daily, weekly or monthly recurrence, with an end date or occurrence count.
  • An external encoder over RTMP or RTMPS, an SRT listener, or the browser studio.
  • A private encoder preview before you go live; stream status with viewer count and latency mode.
  • Viewer registration, a waiting room, a live DVR window, and a replay that can be held for approval.
  • Finished broadcasts can be saved to the Library as a private MP4.

Produce in the browser

  • Scenes with templates, lower thirds and a logo; take a scene to change the live output.
  • Present a PDF or PowerPoint deck of up to 100 MB and 500 slides. PowerPoint import uses LibreOffice Impress on the machine running CuePorch.
  • Audio mixer, audience Q&A and polls shown on screen.
  • Invite up to seven guests by one-use link; guest links need a reachable HTTPS address outside localhost.

Architecture

Three languages, each with one job.

The README states the split plainly. Flask and Waitress serve the institutional UI and API; PeerTube owns transcoding and hosted playback.

Python
The institutional service, Vimeo importer, grants, approval policy, delivery worker and publication queue.
TypeScript
The operator, creator, viewer and screening interfaces, built with tsc and with hls.js 1.6.18 as its one dependency.
Rust
A thin desktop launcher that starts the bundled service and opens your browser. It accepts --data PATH and --headless.
PeerTube
Public hosting and transcoding. Bring an existing host or let the launcher provision one with Compose.
CivicCast (optional)
A station can hand its cable file package and caption sidecar to CuePorch. CivicCast keeps schedule, playout and local recording.
Ports
Defaults are 19001 for the app, 19000 for PeerTube HTTP and 11935 for RTMP, each adjustable for additional institutions.

Install

Install on the machine that will host it.

These steps come from the README for the 0.2.0 release baseline. Local library and exhibition work can begin before a video host is connected.

Windows

  1. Run the signed Setup EXE and keep the suggested library folder.
  2. Open CuePorch from the Start menu.
  3. Enter your institution name, choose Save setup, then Open operator console.
  4. To publish online, add your PeerTube host’s HTTPS address and credentials.

The installer bundles Python and FFmpeg. To provision a local host, start a Docker-compatible Linux container engine and select Set up a local video host.

macOS and Linux

  1. Install the macOS package and open CuePorch from Applications, or install the Debian package and launch it from the applications menu.
  2. Use --data PATH to open an existing library.

The Mac package carries an ad-hoc signature and is not notarized by Apple. Linux packages are tested on Ubuntu 24.04 amd64.

From source

python launch.py ../station \
  --institution station \
  --existing-peer https://video.example.org

Set PEERTUBE_USERNAME and PEERTUBE_PASSWORD first. Omit --existing-peer to provision a host. Building packages needs Python 3.13, Rust, Node.js and PyInstaller; see the README.

Upgrading an existing institution: stop the previous version, back up its complete private data directory and video host, then point Setup at the folder containing operator.json and institution.sqlite. The operations guide covers public deployments and recovery. Checksums for the three 0.2.0 installers are in SHA256SUMS.

Project status

What has been tested, and what has not.

Version 0.2.0 is the public release baseline. The main branch contains later development work that the baseline does not describe.

Tested On three platforms

  • Fresh and upgraded libraries on Windows x64, macOS 15 Apple Silicon and Ubuntu 24.04 amd64.
  • Restricted exhibition playback and real PeerTube publishing from the installed packages.
  • A 0.1.0 station library kept its watch URL, video identity and operator keys on upgrade.

Limits Of that testing

  • The tests used short fixtures and a simulated Vimeo account.
  • Full-scale migration time, production Vimeo OAuth and station cutover are unmeasured.
  • Physical cable reception, public DNS cutover and staffed support were not observed.

Gaps Known

  • Per the acceptance record: historical analytics, commerce, showcase reconstruction and Vimeo-specific player scripting.
  • The Vimeo comparison gives no row full-equivalence credit.
  • Native macOS builds are not notarized.

Read the evidence yourself: the acceptance record and the Vimeo feature comparison. The comparison is a 0.1.0 snapshot, so some workflows it lists as missing now have screens in the current source. The manual describes the current behavior.
